## Схема БД

| таблица | что хранит |
|---|---|
| `users` | роль `executive` / `manager` / `client` / `subcontractor`; `client_company_id` или `subcontractor_id`; `auth_user_id` — связь с Supabase Auth |
| `client_companies` | 8 компаний: код, наименование, БИН |
| `contracts` | номер, даты, срок по тексту, `renewal` (`auto_annual` / `by_agreement` / `none`), `status` на дату `status_as_of`, НДС, условия (`terms`), текст скана и найденные инъекции |
| `contract_addenda` | ДС №24 Модена, ДС №61 Лира, ДС №1 Вента: даты подписания и вступления, итог из документа |
| `facility_objects` | город, объект, площадь, внешняя и фасадная площадь, группа, услуги, тариф KZT (пусто — «по заявке»), ставка за м², базис и ставка НДС, `subcontractor_id` |
| `subcontractors` | P01, P23, P24 |
| `document_source_references` | файл, страница или страницы, лист, строка, пояснение; M2M с договорами, ДС, объектами и спорными условиями |
| `disputed_conditions` | Q-01 … Q-11: severity, topic, issue, ask, статус, кто и когда закрыл |
| `shift_schedules` | месяц, объект, субподрядчик, число ОПУ, часы, режим (ежедневно / 5/2 / пт–вс) |
| `shift_reports` | отметки смен: дата, табельный код оператора (без ФИО), статус, часы |
| `billing_acts`, `billing_act_lines` | АВР клиентам и акты субподрядчиков, суммы без НДС / НДС / с НДС |

Что сидинг берёт из `contracts.json`, а чего там нет:
- Субподрядчик назначается только по графику (`04_Операторы_и_график_сентябрь.xlsx`), справочник по городам назначением не считается. Из этого графика создаются 12 смен на сентябрь 2026: часы и число ОПУ берутся из текста услуг. Если в договоре их нет (например, у Медеу), поля остаются пустыми.
- Клиент спорного условия определяется по файлам-источникам, которые принадлежат ровно одному договору. У Q-07 клиента нет.
- `shift_reports` и `billing_acts` пустые: в `contracts.json` нет ни отметок смен, ни актов.

## Роли и доступ

| роль | видит | пишет |
|---|---|---|
| executive | всё | всё, пользователи, импорт, удаление |
| manager | всё | компании, объекты, графики, акты, статусы спорных условий |
| client | только свою компанию: договоры, ДС, объекты, спорные условия, графики и отметки по своим объектам, свои АВР, назначенных субподрядчиков | ничего |
| subcontractor | только объекты из своего графика смен — адрес, площадь, услуги, график; **без** тарифа, ставки за м², НДС, договора и клиента; свои графики, отметки и акты | отметки смен по своим графикам |

В Supabase доступ задают политики RLS (`db/rls.sql`), в FastAPI — `app/access.py`. Бекенд подключается ролью-владельцем, которую RLS не ограничивает, поэтому правила продублированы в коде.

Цены от субподрядчика скрыты на уровне столбцов. RLS умеет отбирать только строки, а права на столбцы в Supabase общие для всех пользователей `authenticated`. Поэтому прямого доступа к `facility_objects` у субподрядчика нет, и свои объекты он читает через вью `subcontractor_facility_objects` (`db/rls_0003_subcontractor_view.sql`). В API ту же роль играет схема `FacilityObjectForSubcontractor`.

### Демо-режим: переключатель ролей
Чтобы показать на защите, что каждая роль видит своё, фронт получает токен демо-пользователя выбранной роли без пароля. Это работает только при `DEMO_MODE=1`, иначе `/auth/demo-token` отвечает 404.

```bash
cd backend
.venv/bin/python -m scripts.create_demo_users   # руководитель, менеджер, клиент «Модена», субподрядчик P23
DEMO_MODE=1 .venv/bin/uvicorn app.main:app
```

У демо-пользователей нет пароля, войти под ними обычным способом нельзя. Данные отбирает сервер, а интерфейс только скрывает колонки, которых в ответе нет.

На вкладке объектов два вида подсветки:
- **«Субподрядчик не назначен»** — объекта нет в графике (Q-07).
- **«Нет в графике смен»** — объект выпал из графика, хотя другие объекты того же договора в этом городе в графике есть. Пример — бутик Капри в ТРЦ «Арал Молл» (Q-03).

### Supabase
1. Задать `DATABASE_URL=postgresql+psycopg://postgres:<pwd>@db.<project>.supabase.co:5432/postgres` и `JWT_SECRET`.
2. `alembic upgrade head` создаст таблицы и RLS. Другой путь — выполнить `db/schema.sql` в SQL Editor.
3. `python -m scripts.seed_data ../data/contracts.json`.
4. Пользователям Supabase Auth заполнить `users.auth_user_id`: `create_user ... --auth-user-id <uuid>`.

`db/local_supabase_stub.sql` (заглушка `auth.uid()` и ролей) нужен только для локального PostgreSQL, на Supabase его не применять.

## API v1: три вопроса руководителя

| эндпоинт | кто | что отвечает |
|---|---|---|
| `GET /api/v1/analytics/growth-vector?as_of=` | руководитель, менеджер | Куда развиваться: выручка без НДС, ₸/м², клиенты, назначенные субподрядчики, выручка под риском по городам и группам I/II/III; маржа по актам субподрядчиков; рекомендации |
| `POST /api/v1/calculator/estimate-object` | руководитель, менеджер | Сколько стоит новый объект: смета по нормативам пакета (строки ФОТ, материалов, гигиены, инвентаря, оборудования, спецодежды), бюджет субподрядчика, маржа IC, цена без НДС и с НДС, сравнение с бюджетом клиента и с похожими объектами |
| `POST /api/v1/contracts/audit-scan` | руководитель, менеджер | Всё ли в порядке с договором: `contract_id` из базы, `text` или `pdf_base64`. Проверяет арифметику, сроки, работы после окончания договора, НДС и инъекции |
| `GET /api/v1/contracts/discrepancies?severity=&client_id=&status=` | все роли, клиент — только свои | Реестр Q-01…Q-11 с источниками (файл, страницы, лист, строка) |

**Смета нового объекта** считается по нормативам пакета организаторов, как в `01_Смета_пример_Орда_Трейдинг.xlsx`. Код — `app/services/estimate.py`, нормативы — `app/services/norms.py`:
- `data/07_Нормативы.json` — вознаграждение (10,1 %) и админрасходы (1 %) субподрядчика, маржа IC (15 %), платформа занятости (6 %), НДС по датам;
- `data/09_Нормы_для_сметы.xlsx` — производительность по сегментам, ставки ОПУ по графикам, коэффициенты городов, расход и цены материалов, гигиены, инвентаря, оборудования и спецодежды, генуборка, минимальная маржа (10 %).

Порядок расчёта:
1. ОПУ базовой уборки = площадь ÷ производительность сегмента ÷ часы смены, с округлением вверх.
2. ФОТ (с генуборкой и gross-up платформы), материалы, гигиена, инвентарь, оборудование и спецодежда дают себестоимость.
3. Себестоимость + вознаграждение + админрасходы = бюджет субподрядчика.
4. Бюджет субподрядчика + маржа IC = цена без НДС, затем начисляется НДС.

Если задан бюджет клиента, сервис показывает запас или превышение и маржу, которая остаётся в рамках бюджета. Ниже 10 % — предупреждение «только с согласия директора». Контрольная заявка Z-01 из `10_Заявки_на_расчёт.xlsx` совпадает со сметой-примером до копейки (`tests/test_estimate.py`). Справочник сегментов и графиков: `GET /api/v1/calculator/norms`.

**Маржа по факту.** `python -m scripts.import_actuals ../data/05_Факт_сентябрь_2026.xlsx` загружает акты субподрядчиков (P01, P23, P24) за сентябрь 2026 и сопоставляет строки объектам. После этого `growth-vector` считает маржу как «выручка без НДС − акт». Проверки актов:
- **`arithmetic`** — ИТОГО акта не равно сумме строк. Акт P24 завышен на 15 000 ₸.
- **`act_mismatch`** — акт ≠ 85 % цены клиента без НДС.

**Claude API** (`audit-scan` для `text`/`pdf_base64`). Ключ берётся из `ANTHROPIC_API_KEY`. Модель `claude-opus-5-5` (переменная `CLAUDE_MODEL`), effort `medium` (`CLAUDE_EFFORT`), structured outputs и серверный fallback при отказе модели. Модель только извлекает поля, а арифметику, сроки и НДС проверяет код. Защита от инъекций:
1. Строки-инструкции вырезаются до отправки.
2. Документ передаётся как данные, а модель перечисляет найденные в нём инструкции.
3. Сумма, которой нет в тексте, в проверки не попадает.

Python 3.9 в проекте ограничивает SDK версией `anthropic` 0.x (1.x требует Python 3.10+). На живом API разбор пока не проверялся: в тестах Claude подменён.

## Пилот рейтинга операторов (docs/OPERATOR_RATING_PROPOSAL.md)

Новая роль `operator` — личный вход (`POST /auth/token`), видит только свои отметки смен, свой рейтинг не видит (это для персонала).

```bash
.venv/bin/python -m scripts.create_operator OP-900 P23 "Оператор Демо"
.venv/bin/python -m scripts.create_user op900@icgroup.local <пароль> operator --operator-code OP-900
```

| эндпоинт | роли | что делает |
|---|---|---|
| `GET /api/v1/operators`, `POST /api/v1/operators` | список — все (видят по своим правам); создание — персонал | карточка оператора: код, субподрядчик, отображаемое имя |
| `POST /shift-reports` (поле `operator_id`) | персонал, субподрядчик | при статусе done/partial начисляет баллы `shift_base` = часы × вес статуса × 10 |
| `POST /api/v1/shift-reports/{id}/rating` | персонал, клиент — только по своим объектам | оценка 1–10 по 4 критериям (чистота, качество, оперативность, вежливость); любой балл ниже 6 требует комментария; начисляет `rating_adjustment` = (средний балл − 5) × 20 |
| `GET /api/v1/operators/ranking?as_of=` | персонал | рейтинг за календарный квартал: сумма баллов, место, фиксированная премия по порогам (топ 10% — 50 000 ₸, 30% — 25 000 ₸, 70% — 10 000 ₸) |

Баллы — лента (`OperatorPointsEntry`), не просто счётчик: каждая запись ссылается на смену/заявку и причину, рейтинг — всегда пересчитываемая проекция этой ленты за квартал, а не хранимое число. Коэффициенты формулы — в `.env` (`OPERATOR_POINTS_PER_HOUR` и т. д.), см. `app/config.py`.

### Разовые заявки, фото, автоприоритет, премия (этапы 2–4, реализовано)

Новый слой поверх договоров (`CleaningOrder`) — не замена `Contract`/`FacilityObject`. Цена и баллы считаются от площади и уровня качества (пилотные ставки `ORDER_RATE_*` в `.env`, см. `app/config.py` — готового тарифа на разовые выезды в пакете организаторов нет).

| эндпоинт | роли | что делает |
|---|---|---|
| `POST /api/v1/orders` | персонал, клиент (только своя компания) | заявка: город, площадь, качество (поверхностная/средняя/генеральная), бригада (1–2 / команда / «другое»), пожелания; цена = площадь × тариф качества |
| `GET /api/v1/orders`, `GET /api/v1/orders/{id}` | все роли по своим правам (клиент — свои, субподрядчик/оператор — назначенные) | список и карточка заявки |
| `POST /api/v1/orders/{id}/assign` | персонал | назначить оператора вручную |
| `POST /api/v1/orders/{id}/auto-assign` | персонал | автоназначение: верхний по рейтингу квартала среди свободных операторов без незавершённой заявки; при заданном `preferred_city` у оператора — только заявки в этот город |
| `POST /api/v1/orders/{id}/complete` | назначенный оператор, персонал | завершение; начисляет `order_base` = площадь × 0,05 баллов |
| `POST /api/v1/orders/{id}/photos`, `GET /api/v1/orders/{id}/photos` | назначенный оператор (загрузка), персонал/клиент (просмотр) | фото после уборки — файл на диске (`backend/storage/order-photos/`), раздаётся статикой; `ai_review_status` зафиксирован как `not_evaluated` — задел на будущее, не оценивается |
| `PATCH /api/v1/operators/{id}/preferred-city` | штат — любому; оператор — только себе и только если он в топ-30% текущего рейтинга квартала | «лидер выбирает район»: приоритет автоназначения заявок в этом городе |
| `POST /api/v1/operators/bonus/close` | персонал | закрытие периода (`month`/`quarter`): снэпшот `OperatorBonusRecord` по текущей ленте баллов, идемпотентно по (оператор, период) |
| `GET /api/v1/operators/bonus` | все роли по своим правам | история начисленных премий |

Фронтенд: вкладки «Рейтинг операторов» и «Разовые заявки» в операционной консоли (`components/ranking-panel.tsx`, `components/orders-panel.tsx`) — те же демо-данные менеджера, что у «Закрытия месяца».

Сознательно не сделано (см. честный список для защиты): личный кабинет оператора с отдельным логином на фронте (роль `operator` в API есть, экрана нет); оценка фото ИИ; фото раздаются статикой без подписанных URL (приемлемо для пилота, в проде — S3 + подписанные ссылки).

## Блокировки выставления АВР клиенту (`POST /billing-acts`, `kind=client_avr`)
| когда | ответ | как снять |
|---|---|---|
| сумма АВР = итог договора/ДС, который не сходится с суммой строк (Модена, ДС №24) | 409 | выставить по сумме строк или исправить итог |
| период АВР позже срока договора, продление только допсоглашением (Спортлайн, Жұлдыз Банк) | 409 | `POST /contracts/{id}/extensions` с номером ДС, датой подписания и новым сроком (`extends_to`) — только руководитель или менеджер |
| договор истекает внутри месяца АВР, а АВР — за дни после даты окончания | 409 с допустимыми днями и суммой по тарифам за эти дни | выставить АВР с `service_from`/`service_to` по дату окончания включительно |

Договоры с автопролонгацией не блокируются, по ним выдаётся находка `renewal_unconfirmed`. Отметка о продлении учитывается во всех проверках: после неё находки `expired` и `work_after_expiry` по договору пропадают.

## Автопроверки (`GET /checks?as_of=2026-10-16`, только персонал)
| kind | что значит |
|---|---|
| arithmetic | итог документа (договора или ДС) ≠ сумма строк объектов; у Модены ДС №24 даёт +10 000 |
| line_arithmetic | площадь × ставка за м² ≠ тариф; округление до 100 тг с отклонением ≤ 50 ошибкой не считается |
| expired | срок истёк, продлить можно только допсоглашением |
| expiring | срок истекает в ближайшие 90 дней, автопролонгации нет |
| renewal_unconfirmed | исходный срок прошёл, договор действует по автопролонгации — нужно подтверждение |
| vat_rate | ставка ≠ 16 % в периоде после 01.01.2026, с пересчётом базы |
| vat_unspecified | цена указана «с НДС», ставка не названа |
| prompt_injection | в тексте документа посторонняя инструкция; цифры из текста не берутся |
