# ТЗ для ИИ-ассистента: запустить проект IC Group и дописать фронтенд

Этот файл — задание для ИИ-ассистента (Claude Code, Cursor, Codex и др.) участницы команды.
Выполняй строго по порядку: **этап 1 (запуск и проверка) → этап 2 (фронтенд)**. Пока этап 1 не пройден целиком, код не пиши.

---

## 0. Правила, которые действуют всегда

1. В корне репозитория лежит `AI_rules.md` (его выдали организаторы хакатона). Прочитай его и следуй ему — он важнее этого файла. Журнал сессии ведётся в общем файле `.ai/session-notes.md`: **только дописывай записи в конец**, ничего не удаляй и не переписывай — этот файл общий для всей команды.
2. Бекенд — источник истины. Фронтенд **не считает деньги** (НДС, маржу, итоги) и **не решает, кому что видно** — он показывает то, что вернул сервер.
3. Не меняй код в `backend/` без согласования с владелицей бекенда. Если для экрана не хватает данных из API — опиши, какой эндпоинт нужен, и спроси.
4. Никаких секретов во фронтенде: ни паролей, ни ключей API. Вход в демо — только через `POST /auth/demo-token` (см. ниже).
5. Не коммить `.env.local`, `node_modules/`, `.next/`, `backend/.venv/`, `backend/*.db`.

## Этап 1. Запустить и проверить

Требования: **Python 3.9+**, **Node.js 18+**, macOS/Linux. Два окна терминала.

### 1.1. Бекенд (окно 1)

```bash
cd backend
python3 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/alembic upgrade head
.venv/bin/python -m scripts.seed_data ../data/contracts.json
.venv/bin/python -m scripts.import_actuals ../data/05_Факт_сентябрь_2026.xlsx
.venv/bin/python -m scripts.create_demo_users
```

Ожидаемый вывод шагов:
- `seed_data` печатает JSON: `"client_companies": 8`, `"facility_objects": 81`, `"disputed_conditions": 11`, `"shift_schedules": 12`.

Если seed повторно отказывает из-за отметок смен — добавь `--force`. Если порт занят (`EADDRINUSE`) — найди процесс `lsof -nP -iTCP:8000 -sTCP:LISTEN` и останови его (или спроси участницу).

## Этап 2. Фронтенд

### 2.1. Как устроен фронтенд (соблюдай)

- Next.js 14, App Router, **строгий TypeScript**, Tailwind, компоненты в стиле **shadcn/ui** в `components/ui/` (Badge, Button, Card, Dialog на Radix, Table, NativeSelect, Skeleton). Новые UI-примитивы — туда же, в том же стиле (`cva` + `cn`).
- Состояние: **TanStack Query** для данных с сервера (`hooks/queries.ts`), **Zustand** для сессии (`store/session.ts`). Ключ кэша **всегда включает роль**: `["имя", role, ...фильтры]`.
- API-клиент — `lib/api.ts` (`request<T>`, `ApiError` со `status`). Типы ответов — `lib/types.ts`, повторяют `backend/app/schemas.py` и `schemas_v1.py`. Деньги и площади приходят **строками** (Decimal) — форматируй через `formatKzt` / `formatArea`, не превращай в float для расчётов.
- Цвета — только токены (`bg-destructive`, `text-muted-foreground`, `bg-warning` …), тёмная тема работает сама. Никаких хардкод-цветов.
- Каждый экран обрабатывает: загрузку (Skeleton), ошибку (`error.message` от сервера — показывай как есть, сервер пишет понятные русские сообщения), пустой список.
- Права: показывай вкладку/кнопку только если роли она нужна, **но не полагайся на это** — сервер всё равно ответит 403. 403 показывай как «Недоступно для вашей роли».
- Мобильная ширина 375 px: без горизонтального скролла страницы (таблицы — внутри `overflow-x-auto`).

### 2.2. API, которое понадобится

Все запросы — с `Authorization: Bearer <token>`. Полные схемы — `http://localhost:8000/docs`.

| метод и путь | роли | что даёт |
|---|---|---|
| `GET /api/v1/analytics/growth-vector?as_of=YYYY-MM-DD` | руководитель, менеджер | выручка, ₸/м², клиенты, выручка под риском, маржа по актам — по городам (`by_city`) и группам I/II/III (`by_group`); `recommendations[]` (priority, city, action, reason); `assumptions[]` |
| `GET /api/v1/calculator/norms` | руководитель, менеджер | списки `segments`, `schedules`, коэффициенты городов, ставки НДС, маржа IC |
| `POST /api/v1/calculator/estimate-object` | руководитель, менеджер | смета: `lines[]` (section, name, qty, monthly_net…), `summary[]`, `price` (cost, subcontractor_budget, ic_margin, net, vat, gross), `budget` (gap, margin_at_budget_pct), `benchmark`, `warnings[]` |
| `POST /api/v1/contracts/audit-scan` | руководитель, менеджер | тело: ровно одно из `contract_id` / `text` / `pdf_base64`; ответ: `verdict` (ok/warnings/problems), `findings[]`, `removed_instructions[]`, `extraction` |
| `GET /api/v1/contracts/discrepancies` | все (клиент — свои) | реестр Q-01…Q-11 с `sources[]` |
| `GET /checks?as_of=` | руководитель, менеджер | все находки автопроверок (`kind`, `severity`, `message`, `expected`, `actual`, `difference`) |
| `GET /contracts`, `GET /contracts/{id}` | персонал, клиент — свои | договоры с `addenda[]` (в т.ч. `extends_to`), `status`, `renewal` |
| `POST /contracts/{id}/extensions` | руководитель, менеджер | отметка о продлении: `{number, signed_at, extends_to, summary?}` |
| `GET /billing-acts`, `POST /billing-acts` | GET — все по своим правам; POST — персонал | АВР клиентам и акты субподрядчиков; POST может вернуть **409** (см. 2.4) |
| `GET /schedules`, `GET /shift-reports`, `POST /shift-reports` | по ролям | графики смен и отметки; субподрядчик может отмечать смены только по своим графикам |

Роли и коды: `executive` — руководитель, `manager` — менеджер, `client` — клиент (демо: Модена), `subcontractor` — субподрядчик (демо: P23).

### 2.3. Задачи (в порядке приоритета)

Каждая задача — отдельный шаг. После каждого шага: `npx tsc --noEmit`, проверка в браузере под нужными ролями, запись в журнал.

**Задача 1. Экран «Куда развиваться» (`growth-vector`)** — новая вкладка для руководителя и менеджера.
- Сверху — рекомендации карточками, цвет по `priority` (high — destructive, medium — warning, low — muted).
- Таблица по городам: город, объектов, клиентов, выручка ₸/мес без НДС, ₸/м², выручка под риском, маржа % (если есть), «по заявке». Сортировка по выручке (как отдал сервер).
- Переключатель «города / группы I-II-III».
- Внизу мелким шрифтом — `assumptions` (на чём основан расчёт).
- Приёмка (as_of=2026-10-16): первые две рекомендации — «Перезаключить договор SL-2023/114…» и «…ZB-2023-0457…»; в строке «Алматы» маржа **15.0 %** и `objects_with_acts` = 10; клиенту и субподрядчику вкладка не показывается.

**Задача 2. Экран «Сколько стоит новый объект» (калькулятор сметы).**
- Форма: город, сегмент (select из `/calculator/norms`), площадь м², число санузлов, график базовой уборки (select), поддерживающая уборка — список строк «позиций × график» с добавлением/удалением, гигиена (да/нет), генуборка (да/нет), бюджет клиента ₸/мес с НДС (необязательно), НДС 12/16 (по умолчанию пусто = по дате).
- Результат: свод (`summary`) с долями, блок цены (себестоимость → бюджет субподрядчика → маржа IC → цена без НДС → НДС → с НДС), блок бюджета (запас/превышение, маржа в бюджете), ориентир по рынку, `warnings` заметно.
- Строки сметы (`lines`) — раскрывающимися секциями: ФОТ, материалы, гигиена, инвентарь, оборудование, спецодежда.
- Ошибки 422 (неизвестный сегмент/график) — под формой текстом сервера.
- Приёмка — контрольная заявка Z-01 из `data/10_Заявки_на_расчёт.xlsx`: Алматы, «Офисы и бизнес-центры», 1150 м², 4 санузла, «5/2 утро 4 ч», поддержка «1 × 5/2 полный день 9 ч» и «1 × 5/2 день/вечер 4 ч», гигиена да, генуборка да, бюджет 3 100 000, as_of 2026-10-05 →
  ОПУ 8 (базовых позиций 6), цена без НДС **2 039 588,64 ₸**, с НДС **2 365 922,82 ₸**, маржа IC **15,0 %**, запас бюджета **+734 077,18 ₸**.

**Задача 3. Экран «Проверка договора» (`audit-scan`).**
- Три режима: выбрать договор из списка (`/contracts`) → `contract_id`; вставить текст; загрузить PDF (FileReader → base64 без префикса `data:`).
- Результат: крупно `verdict`; находки списком, сортировка critical → high → medium → low; у арифметики показать «в документе / по строкам / разница»; блок «Вырезанные инструкции» (`removed_instructions`) отдельно и заметно — это защита от промпт-инъекций; блок `extraction.amounts_not_in_text`, если не пуст.
- 503 (нет ключа Claude) — понятное сообщение «Разбор текста недоступен: на сервере не задан ANTHROPIC_API_KEY»; режим «договор из базы» работает без ключа.
- Приёмка: договор MR-01/2020 → находка arithmetic, разница 10 000; SL-2023/114 → expired (high) и work_after_expiry (critical, «2026-09»).

**Задача 4. АВР и продление договора (менеджер).**
- Список АВР/актов (`GET /billing-acts`), форма АВР: клиент, договор, месяц, необязательно дни `service_from`–`service_to`, НДС, строки (описание, сумма без НДС).
- **409 — главное в этой задаче:** показать текст сервера целиком (там сказано, что сделать: выставить по строкам, указать дни, внести продление) и не очищать форму.
- Кнопка «Отметить продление» у договора → форма `extensions`; после успеха — обновить договор и дать повторить АВР.
- Приёмка: АВР по SL-2023/114 за 2026-09 → 409 «истёк 2024-03-31»; после продления до 2026-12-31 тот же АВР проходит; АВР Модены на 5 571 400 → 409, на 5 561 400 → проходит.

**Задача 5 (если останется время).** Экран «Автопроверки» (`/checks`) с фильтрами по `kind`/`severity`; для субподрядчика — экран отметок смен по своим графикам (`/shift-reports`).

### 2.4. Бизнес-правила, которые фронтенд не должен ломать

- Итог ДС №24 Модены (5 571 400) не подтверждён — счёт по нему сервер не выставит. Не предлагай его как сумму по умолчанию.
- Договоры Спортлайн и Жұлдыз Банк истекли; АВР — только после отметки о продлении и только в пределах срока, в месяце окончания — по дату окончания.
- Субподрядчик не видит тарифы, НДС и клиента — не пытайся получить их обходными запросами.
- Строки, вырезанные как промпт-инъекции, показывай как предупреждение, никогда не как условия договора.
- Открытые вопросы данных (не решай их во фронте): база НДС у Медеу 12 % или 16 % (Q-09); назначение субподрядчиков вне Алматы (Q-07).
